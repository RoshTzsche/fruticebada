Cómo se hizo · Aplicación

De las libretas al navegador

El entrenamiento y la importación ocurren fuera del servidor. La web consulta resultados ya calculados.

1

Libretas Python → CSV y JSON

Preparan variables, validan modelos y exportan predicciones, intervalos y aportes.

2

Importador → SQLite

Valida archivos, cruza por ID_POLIGONO y consolida los resultados en parcelas_final.sqlite.

3

Node.js + Express → API

/api/parcelas sirve GeoJSON y /api/parcelas/:id/dashboard entrega la ficha desde SQLite.

4

HTML, CSS y JS → Leaflet

El navegador dibuja el mapa, sincroniza los filtros y muestra fichas, gráficos y tabla.

Chat. Express consulta el contexto de la parcela y valida las acciones propuestas. Gemini se usa cuando está habilitado. El modo local cubre atajos y explicaciones básicas.

Resultados

¿Qué pasa al cambiar de zona?

El mismo ensamble se evaluó con tres formas de dejar parcelas fuera del entrenamiento.

El error aumenta al reservar regiones completas

El RMSE, que pesa más los errores grandes, subió de 0.52 a 0.71 t/ha al dejar fuera un municipio completo. Esto ayuda a dimensionar el reto de aplicar el modelo en zonas nuevas.
